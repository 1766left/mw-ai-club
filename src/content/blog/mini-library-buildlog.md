起点是一张便利贴，上面写着："小区里想借本书，得先在群里问一圈，还要等对方看到消息。"

这件事看起来很小。但我们把它拆开之后，发现问题比想象的多。

## 把麻烦拆开

我们一共列了 11 条「麻烦」，最后归成四类：

1. **找不到**——不知道谁手里有这本书。
2. **不确定**——问了之后对方不回，不知道还算不算数。
3. **不方便**——约时间、约地点、书怎么交接。
4. **不好意思**——借了忘了还，或者还的时候对方不在家。

第 4 类是我们最开始完全没想到的。它不解决技术问题，但决定了这个工具会不会有人用。

## 一个决定性的设计

最初的版本里，借书是一个「申请—同意」的流程。测试的时候发现：很多人不愿意点"申请"，因为觉得在麻烦别人。

后来我们把流程反过来——**拥有书的人先表达"我愿意借"**，想借的人只是去"认领"。这一改，测试里的操作意愿明显变了。

```text
旧流程：想借的人 → 申请 → 书主同意 → 约时间
新流程：书主标记"可借" → 想借的人 → 认领 → 自动约定交接点
```

## 学到了什么

最有用的一句话来自一位试用的家长：**"你们这个界面，让我觉得我不是在申请什么，是在挑东西。"**

我们本来以为自己在做一个"借书工具"。实际上我们做的是一个"让人不觉得欠人情"的工具。这两个差别，决定了所有交互细节。
