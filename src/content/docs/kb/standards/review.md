## 评审时别人会做什么

只有一件事：**在你的东西上找卡住的地方。**

他们不会夸你界面好看，也不会说"挺不错的"。他们会：

- 点一个按钮，然后停住
- 问"如果我这里点错了会怎样"
- 问"这个字是什么意思"

## 你应该准备什么

1. **能跑的东西**（不是 PPT，不是截图）
2. **一句话说清楚给谁用**
3. **一个你想被回答的具体问题**，比如"你觉得心愿单这个入口好找吗"

第 3 条最容易被忽略。没有具体问题，评审就会变成泛泛的意见交换，收获很小。

## 被挑刺的时候

| 不要 | 要 |
| --- | --- |
| 解释"这里其实可以……" | 记下来，先别说话 |
| 反驳"这个我知道，只是没做" | 问"你刚才以为会发生什么？" |
| 只说"好的我改" | 复述你理解的问题 |

"你刚才以为会发生什么"这句话特别有用——它暴露的是设计意图和使用者理解之间的差。

## 评审后

当天写一份记录，放进项目文件夹的 `05 记录/`：

```text
日期：2026-10-20
试的人：3 位家长
停住超过 5 秒的地方：
- 首页"认领"按钮，2 人不知道点了会怎样
- 借还记录页，1 人找不到还书入口
打算改：
- 按钮文案改成"我要借这本"
- 还书入口提到顶部
不改（这次）：
- 心愿单排序（不在第一版范围内）
```

最后一行很重要。**不是所有意见都要改**——但要写下为什么不改。
