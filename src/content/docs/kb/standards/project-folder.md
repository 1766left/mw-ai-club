## 骨架

```text
<项目名>/
├── README.md          ← 项目是什么、给谁用、怎么跑起来
├── 01 需求/           ← 用户是谁、解决什么问题、不做什么
├── 02 设计/           ← 草图、截图、配色
├── 03 代码/           ← 真的能跑的东西
├── 04 素材/           ← 图片、音频、字体
└── 05 记录/           ← 每次试用的反馈、改了什么
```

编号不是装饰。它决定了别人打开你项目时，第一步看哪里。

## 命名

| 对象 | 规则 | 好 | 不好 |
| --- | --- | --- | --- |
| 项目文件夹 | 小写英文，连字符 | `mini-library` | `新建文件夹(2)` |
| 文档 | 中文可以，别有空格 | `统一PRD.md` | `PRD 最终 改3.md` |
| 代码文件 | 小写英文，见名知意 | `book-shelf.ts` | `test2.js` |
| 版本 | 用 git，不要用文件名 | `git commit` | `最终版-真的最终.md` |

## 最常犯的错

**用文件名管理版本。** `需求.md`、`需求-改.md`、`需求-最终.md`、`需求-最终2.md`——到了第四个，没人知道哪个是真的。

用 git。不会用 git 就先问，别再复制文件。

## README 的第一行

必须是这一句，具体到能判断做没做到：

```text
用户能在 30 秒内找到一本可以借的书。
```

不是"做一个借书系统"。写不出这一句，说明项目还没想清楚。
