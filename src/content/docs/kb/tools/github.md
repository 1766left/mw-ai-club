## 为什么非要用它

不是因为"程序员都用"，是因为它解决三个具体麻烦：

1. **改坏了回不去。** 每次提交都是一个存档点，能回退到任何一个版本。
2. **两个人同时改会打架。** 它会告诉你哪一行冲突了，而不是互相覆盖。
3. **东西会丢。** 放在自己电脑上的项目，换台机器就没了。

## 最小用法

只要会这四个动作，就够用了：

```bash
git add .
git commit -m "改了书架页的排序"
git push
git pull
```

## 命名约定

| 类型 | 格式 | 例子 |
| --- | --- | --- |
| 仓库 | 小写英文 + 连字符 | `mini-library` |
| 提交信息 | 动词 + 改了什么 | `fix: 书架页排序错乱` |
| 分支 | `feat/功能名` 或 `fix/问题名` | `feat/wishlist` |

## 小组协作的最小规则

- 每天开始前先 `git pull`
- 不要两个人同时改同一个文件——先分好谁改哪一块
- 提交信息写"改了什么"，不要写"update"

## 公开还是私有

涉及真实用户数据的项目（例如社区借书），**仓库先设为私有**。等确认里面没有账号、密钥、真实姓名电话，再考虑公开。
