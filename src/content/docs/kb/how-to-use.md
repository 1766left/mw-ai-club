你大概会在三种情况下打开这里。每种情况给你一条最短路径。

## 情况一：刚进 Club，什么都不会

按这个顺序读，大概 20 分钟：

1. [发现一个真问题](/kb/method/find-a-problem/)——先搞清楚你要做的到底是什么
2. [一个项目从哪开始](/kb/method/four-steps/)——四步，第一步做什么
3. [怎么跟 AI 提要求](/kb/method/prompting/)——第一次提问的模板，直接抄
4. [项目文件夹怎么建](/kb/standards/project-folder/)——建好再用，省得以后搬

看完先别急着动手。**先去看 `/projects` 里别人做的东西**，找一个你觉得"这个我好像也能改"的，从改它开始，比从零开始容易得多。

## 情况二：正在做一个项目

按需查，不要通读：

| 你在做什么 | 去看 |
| --- | --- |
| 想不清楚需求 | [需求文档怎么写](/kb/standards/prd/) |
| 不知道用哪个工具 | [工具与平台](/kb/tools/workbuddy/) |
| 卡在 AI 生成的代码里 | [Vibe coding 的三个坑](/kb/pitfalls/vibe-coding/) |
| 要给别人看成果 | [评审：怎么被挑刺](/kb/standards/review/) |
| 快到截止日期了 | [最后一周为什么总是崩](/kb/pitfalls/last-minute/) |

## 情况三：卡住了

先做这三件事，再找人：

1. **把问题写成一句话。** "页面点了没反应"不够，要写"点『提交』按钮后，控制台报 xxx，页面没有变化"。很多时候，写的过程里答案就出来了。
2. **在知识库搜一次。** 页面右上角有搜索（`Ctrl/Cmd + K`）。
3. **问 AI，但带上你的上下文。** 贴代码、贴报错、说清楚你期望发生什么。

如果三件都做了还是不行，就带着这三样去找老师——这比自己闷一小时有效。

:::caution[一个提醒]
知识库里很多内容标着「待补」。这不影响你使用，但如果你解决了某个「待补」里的问题，请回来把它补上。这是 Club 里最受欢迎的行为。
:::
